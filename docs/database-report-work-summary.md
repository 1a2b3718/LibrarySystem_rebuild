# 数据库设计报告完善工作说明

## 1. 具体完成的工作

本次围绕数据库原理课程报告模板，对图书馆系统的数据库设计报告和相关实现说明进行了补充完善，具体工作如下。

### 1.1 按课程模板重构报告结构

将原有数据库设计报告从简要说明扩展为正式报告结构，新增或完善了以下章节：

- 文档介绍、文档目的、文档范围、术语解释。
- 数据库环境说明。
- 数据库命名规则。
- 需求分析、数据流图、功能模块划分。
- 数据字典、业务规则汇总。
- 概念设计、E-R 图和实体关系说明。
- 逻辑设计、关系模式、函数依赖、范式分析。
- 完整性设计、数据库对象设计、事务与并发控制。
- 安全性设计、数据库备份恢复和日常维护说明。
- 主要成果和小结。

### 1.2 补充完整数据字典

对 `Books`、`Readers`、`Accounts`、`BorrowRecords` 四张核心表逐一补充字段说明，明确了每个字段的类型、长度、是否允许为空、主外键、默认值、业务含义和约束规则。

该部分使报告从“只列关系模式”提升为“可指导建表和验收的数据字典”。

### 1.3 增加数据库原理相关分析

新增函数依赖与范式分析，说明各表主键对非主属性的决定关系，并分析系统满足第一范式、第二范式和第三范式的原因。

同时说明 `BorrowRecords` 表用于分解读者和图书之间的多对多关系，体现关系数据库建模中的联系实体设计。

### 1.4 说明冗余字段与一致性维护

对 `AvailableCopies`、`BorrowedCount`、`IsBorrowable` 等派生字段进行了说明。这些字段可由借阅记录推导，但为了提高常用查询效率保留在表中。

报告明确说明这些字段通过借书、还书存储过程在事务中统一维护，避免库存数量和读者已借数量不一致。

### 1.5 补充事务与并发控制设计

新增事务与并发控制说明，解释 `sp_BorrowBook` 和 `sp_ReturnBook` 如何在一个事务中完成多表更新。

报告中进一步说明借书过程使用 `UPDLOCK, HOLDLOCK` 锁定相关记录，防止多个请求同时借同一本库存不足的图书导致数据不一致。

### 1.6 补充索引、视图、存储过程和触发器说明

完善了数据库对象设计，说明以下对象的作用：

- `vw_OverdueBorrowRecords`：统一逾期未还记录查询。
- `IX_Books_TitleAuthor`、`IX_Readers_Name`、`IX_BorrowRecords_Reader_ReturnDate`、`IX_BorrowRecords_Isbn_ReturnDate`：提升常用查询效率。
- `sp_BorrowBook`、`sp_ReturnBook`、`sp_PayReaderFine`：封装借书、还书和缴罚款业务。
- `trg_CheckOverdueOnBorrow`：限制存在当前逾期未还记录的读者继续借书。

### 1.7 增加账号与读者的一对一约束

在数据库脚本中新增 `UQ_Accounts_ReaderCardNo` 过滤唯一索引，使一个读者最多只能绑定一个账号，同时允许管理员账号不绑定读者。

这一修改使 E-R 图中的“读者与账号一对零或一”关系真正由数据库约束保证。

### 1.8 修正文档与实现不一致之处

系统设计文档中原本写“删除图书或读者前只检查未归还借阅记录”。后端实际实现是只要存在任意历史借阅记录就不允许删除。

本次已将说明修正为“存在任意历史借阅记录则不允许删除”，以保证借阅历史完整性和文档准确性。

### 1.9 补充安全性与维护说明

新增账号角色权限、密码哈希存储、账号启用禁用、前端不能直接访问数据库、数据库备份恢复和日常维护建议。

其中密码部分按当前实现如实说明为“SHA-256 哈希加固定系统盐”，避免报告写成“随机盐”但实现并未支持的情况。

## 2. 改进后的优点

### 2.1 更符合课程模板要求

改进后的报告覆盖模板中的主要栏目，包括环境说明、命名规则、需求分析、数据字典、概念设计、逻辑设计、安全性设计、数据库维护和成果小结，更像正式课程设计报告。

### 2.2 数据库原理体现更充分

新增函数依赖、范式分析、完整性约束、事务、并发控制和索引设计说明后，报告不再只是介绍系统功能，而是能体现数据库原理课程的核心知识点。

### 2.3 数据结构说明更清晰

数据字典详细说明了每张表、每个字段和每条约束，便于老师检查数据库结构，也便于后续维护者理解字段含义。

### 2.4 业务规则和数据库约束对应更明确

报告用业务规则表把“库存不能为负”“读者不能超借”“罚款不能为负”“Reader 必须绑定读者”等规则和具体数据库实现对应起来，增强了设计的可验证性。

### 2.5 数据一致性说明更有说服力

通过说明借书、还书事务以及锁机制，可以证明系统在并发访问下仍能保持库存数量、读者已借数量和借阅记录一致。

### 2.6 文档与实际实现更一致

本次同步修正了删除限制描述，并补充了触发器和账号唯一绑定索引说明，减少了报告和代码脚本之间的差异，降低答辩时被追问的风险。

### 2.7 后续扩展方向更明确

报告最后说明当前模型可以继续扩展预约、续借、图书分类、馆藏位置等功能，体现了数据库设计的可扩展性。
